2. Installation Guide (Docker)

Prerequisites

  • Docker Engine (v20.10+)
  • Docker Compose (v2.0+)
  • License Key (sent via email)

Step 1: Load Images

Unzip the archive and load the Docker images:

docker load < yads-images.tar.gz

Verification:

docker images | grep yads # Should list yads-api and yads-worker

Step 2: Launch

Navigate to the directory and start the stack:

docker compose up -d

3. Setup Wizard (Automated Configuration)

Open http://localhost:8000 in your browser.

You will be automatically redirected to the Setup Wizard.

  • License: Enter your license key.
  • Database: Set a secure password for the database.
  • Initialization: Choose between Upgrade (keep data) or Factory Reset.
  • Admin: Create your personal administrator account.

Done! YADS is now fully configured and ready to use.

3. Technical Architecture

YADS is built on a microservices architecture, orchestrated by Docker Compose.

yads-api

Backend (FastAPI). Manages data, users, and API.

yads-worker

Background Service. Executes scans (Nuclei, Nmap, Chrome).

PostgreSQL

Primary database for persistence.

Redis

Task Queue & Caching Layer.

4. Distributed Workers (Optional)

For large-scale deployments, YADS supports horizontal scaling by running multiple worker nodes across a Docker Swarm cluster.

Prerequisites

  • Docker Swarm initialized on all nodes
  • Network connectivity between manager and worker nodes
  • Redis accessible from all nodes (overlay network)

Step 1: Initialize Docker Swarm

On the manager node (where yads-api runs):

docker swarm init --advertise-addr <MANAGER_IP>

This will output a join command. Run it on each worker node:

docker swarm join --token <TOKEN> <MANAGER_IP>:2377

Step 2: Generate Worker Registration Token

In the YADS UI, go to Settings → Distributed Workers and click "Generate Token".

Copy the token – you'll need it for each secondary worker.

Step 3: Deploy Secondary Workers

Use the Swarm deployment file included in the release:

# Set environment variables export WORKER_REGISTRATION_TOKEN=<your-token> export REDIS_URL=redis://<manager-ip>:6379/0 # Deploy workers across the swarm docker stack deploy -c docker-compose.swarm.yml yads

Step 4: Verify Workers

In the YADS UI under Settings → Distributed Workers, you should see:

  • Active Workers: List of all connected worker nodes
  • Load Distribution: Current task count per worker
  • Health Status: Heartbeat status (updates every 30s)
💡 Tip: Workers automatically reconnect after network interruptions. Tasks from failed workers are requeued automatically.

Worker Control

You can manage workers without restarting services:

  • Suspend: Stop accepting new tasks (finish current ones)
  • Resume: Accept new tasks again
  • Drain: Gracefully shut down after completing all tasks

5. One-Click Updates

YADS includes an in-app update mechanism that pulls the latest Docker image and performs a graceful restart without manual intervention.

How It Works

  1. Check for Updates: Go to Settings and click "Check for Updates"
  2. Review Changes: View the changelog to see what's new
  3. Start Update: Click "Start Update" to begin the process

Update Process

The update process is fully automated:

1️⃣
Pause Queue

Scan queue is paused

2️⃣
Drain Tasks

Active scans complete

3️⃣
Pull Image

Download new version

4️⃣
Restart

Graceful restart

⚠️ Important: Create a backup before updating. Updates can be cancelled during preparation/download phases, but not once restart begins.

Manual Update (Alternative)

If you prefer to update manually or the in-app update fails:

# Pull the latest image docker pull yads/yads:latest # Restart services docker compose up -d --force-recreate

6. SIEM Integration (Splunk)

YADS supports real-time forwarding of security audit events to Splunk for centralized monitoring and SIEM correlation. Events are aligned with the MITRE ATT&CK framework.

Configuration

Add the following environment variables to your docker-compose.yml:

environment: - SPLUNK_HEC_URL=https://splunk.example.com:8088/services/collector - SPLUNK_HEC_TOKEN=your-hec-token-here

Event Types

The following security events are forwarded to Splunk with MITRE ATT&CK technique IDs:

Login Events

Success, Failure (T1078, T1110)

Password Changes

User & Admin reset (T1098)

MFA Events

Enable, Disable, Reset (T1556)

User Management

Create, Delete, Role Change (T1136)

💡 Tip: Create a Splunk dashboard using MITRE technique IDs to correlate YADS events with other security tools. Example search: index=yads mitre_technique_id=T1110*
