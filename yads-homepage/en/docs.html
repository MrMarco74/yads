1. Introduction

YADS is an automated security reconnaissance platform designed to map, analyze, and monitor internet-facing assets. It combines multiple scanning techniques—DNS enumeration, port scanning, web analysis, and vulnerability detection—into a single, easy-to-use interface.

Key Features

  • Asset Discovery: Find subdomains and forgotten infrastructure.
  • 19+ Modular Scanners: Choose individual modules or use pre-built scan profiles for targeted assessments.
  • Vulnerability Scanning: Detect outdated software (CVEs), misconfigurations, and active threats.
  • AI Intelligence Suite: AI-powered finding prioritization, remediation guidance, and natural-language search across all findings.
  • Post-Quantum Cryptography (PQC) Report: Assess your cryptographic posture against quantum-era threats — NIS2/DORA aligned.
  • Module Report Center: Every scanner module has its own dedicated report page with PDF and Excel export.
  • Visual Intelligence: Capture screenshots and visualize network relationships via Attack Path and network graph.
  • Continuous Monitoring: Track changes over time with automatic change detection and alerting.
  • Full EN/DE Platform: UI, PDFs, Excel exports, and AI outputs fully available in English and German.
  • Multi-User & Multi-Tenant: Securely manage multiple teams or clients within one instance.

2. Getting Started

2.1 Initial Setup Wizard (First Run)

Upon the first launch of a new instance, YADS intercepts all traffic and presents a Setup Wizard. You must complete this 4-step process before accessing the dashboard:

  1. License: Enter your valid YADS license key.
  2. Database: Define a secure password for the internal PostgreSQL database. This password is automatically persisted to /app/data/config.env.
  3. Initialization:
    • Upgrade: Preserves existing data and runs schema migrations (use this for updates).
    • Purge (Factory Reset): WARNING: Deletes ALL data and starts fresh.
  4. Admin Creation: Create the first System Administrator account.

2.2 Graphical Setup Tool (GUI)

For a modern and intuitive deployment, use the new Python-based GUI setup tool yads-setup.pyz. It features a user-friendly interface with system dark mode support, network connectivity tests (Ping), and automatic IP resolution.

  1. Unzip the release package (unzip yads-test-release.zip && cd yads-test-release).
  2. Run chmod +x yads-setup.pyz && ./yads-setup.pyz.
  3. The installer automatically checks for dependencies (Docker, Compose) and offers one-click installation for missing components.
  4. Enter your registry token in the GUI to automatically pull Docker images from registry.yads-security.com.
  5. After configuring ports and SSL, the tool generates your .env file and an optimized docker-compose.yml.

Re-running the Setup:
If you need to re-run this wizard (e.g. to factory reset), restart the container with the environment variable SETUP_COMPLETE=false:
docker compose run -e SETUP_COMPLETE=false -p 8000:8000 yads-api
Or manually edit /app/data/config.env to set SETUP_COMPLETE=False and restart.

2.2 Accessing the System

Navigate to your YADS instance (e.g., https://yads.your-domain.com).

  • Login: Enter your username and password.
  • MFA: If enabled, enter your Time-based One-Time Password (TOTP) from your authenticator app.

2.3 Interface Preferences

  • Day/Night Mode: Toggle the Moon/Sun icon in the top navigation bar to switch between Dark (default) and Light themes.

2.4 First Steps

  1. Dashboard: You will land on the main dashboard showing an overview of your targets.
  2. Add Target: Use the input box at the top (or "Add Target" button) to enter a domain (e.g., example.com).
  3. Run Scan: Once added, click the "Scan" button to start gathering data.

2.5 Licensed Features

YADS is a modular platform. While the core discovery and analysis engine is open-source, several advanced features require a valid license key:

  • reports: Advanced PDF and Excel reporting — Executive Summary, Module Reports, Compliance, and Custom Builder.
  • pqc_report: Post-Quantum Cryptography readiness report with CBOM export in CycloneDX format.
  • api: Full REST API access for automated integrations and custom pipelines.
  • scheduled_scans: Recurring automated reconnaissance missions (Daily/Weekly).
  • osint: Brand monitoring and reverse image search via Google Vision API.
  • webhooks: Real-time event notifications for Slack, Discord, or custom endpoints.
  • tenants: Multi-tenancy and client isolation for professional service providers.
  • multilanguage: Full EN/DE platform — UI, reports, AI outputs, and Excel exports in both languages.

3. Dashboard Overview

The Dashboard is your command center.

  • Critical Attention HUD: A prominent alert block at the top highlighting immediate threats (e.g. Expired SSL, Critical Vulnerabilities). If the system is secure, this block will confirm it.
  • Stats Cards: Fast view of Total Targets, Active Scans, and Queue status.
  • Target List: A paginated table of all your monitored domains.
    • Status Indicators: Shows if a scan is Idle, Queued, Running, or Failed.
    • Health Checks: Quick indicators for SSL status, Online status, and Risk Score.
  • Live Activity: The "Active Scans" panel on the right shows real-time progress of running jobs.

4. Target Management

Adding Targets

  • Single: Enter a domain in the dashboard input.
  • Bulk Import: Click the "Import" button to upload a text file (one domain per line) or paste a list.
    • Option: "Verify DNS" checks if domains are resolvable before adding them.

Bulk Actions

Select multiple targets using the checkboxes in the table to perform batch operations: * Bulk Scan: Trigger specific scan modules for all selected targets. * Bulk Delete: Remove targets and their data.

Filtering

Use the column filters in the Table View to find specific targets: * Filter by Name: Search for partial domain matches. * Filter by Status: Show only Failed or Running scans. * Filter by Tags: Organize targets using custom tags.

5. Running Scans

You can run scans in two modes:

Quick Scan

Clicking the "Play" button on a target runs the Default Scan Profile, which includes: * DNS Enumeration * Web Analysis * SSL Check

Custom Scan

On the Target Details page, click "New Scan" to open the advanced selector. You can toggle individual modules: * Subdomain Recon: Finds sub.example.com. * DNS Records: A/AAAA/MX/TXT records. * Web Analyzer: Screenshots, tech stack, and headers. * Typosquatting: Checks for phishing domains (e.g., exampel.com). * CVE Scanner: Checks detected software against vulnerability databases. * Port Scan: Probes common ports (80, 443, 8080, etc.). * Wayback Machine: Looks for historical files and endpoints. * FULL SCAN: Runs all available modules.

Scan Profiles

(New in v1.20) Scan Profiles let you define reusable sets of scanner modules. Instead of toggling individual modules each time, select a profile and all associated modules are activated automatically.

  • Creating Profiles: Navigate to Scan Profiles in the sidebar. Click "New Profile", give it a name (e.g., "Quick Recon", "Full Assessment"), and select which modules to include.
  • Using Profiles: In the target's "New Scan" modal, select a profile from the dropdown to pre-fill all module selections. You can still fine-tune individual modules before launching.
  • Default Profile: One profile can be marked as default — this is what runs when clicking the quick "Scan" button from the target list.
  • Sharing: Profiles are scoped to the tenant and visible to all users within it.

Scheduled Scans

(New in v2.0.5) You can automate your reconnaissance by setting up recurring schedules. 1. Navigate to the Schedules page via the sidebar. 2. Click "Create Schedule". 3. Select a Target and choose a Frequency (Daily or Weekly). * Daily: Runs every 24 hours. * Weekly**: Runs every 7 days. 4. Manage existing schedules (Delete/View Next Run) directly from the list.

Note: Scheduled scans automatically execute the FULL SCAN profile to ensure comprehensive coverage.

6. Analysis Modules

Web Analyzer & OSINT

Visits the page as a real user. * Visuals: Full-page screenshot and favicon. * Technologies: Identifies CMS (WordPress), Server (Nginx), and Frameworks. * OSINT: Extracts emails, phone numbers, and social media links found on the page.

Vulnerability Report (CVEs)

  • Matches version numbers (e.g., "Apache 2.4.49") against known CVEs.
  • Displays severity (CVSS) and descriptions.
  • Note: This logic relies on accurate version detection.

Infrastructure Scanner

  • Geo-Location: Maps the server IP to a physical location.
  • ASN Info: Identifies the hosting provider (e.g., AWS, DigitalOcean).
  • Cloud Check: Detects if the asset is on a major cloud provider.
  • Reputation: Checks IP against spam/malware blacklists.

DNS & Subdomain

  • Passive Recon: Uses public logs (CT) to find subdomains without touching the target.
    • Active Brute-force: Tries common subdomain names.
    • Dangling CNAMEs: Warns if a subdomain points to a non-existent cloud resource (hijacking risk).

Vulnerability Scanning (Active)

(New in v2.0.5) YADS now integrates Nuclei for active vulnerability detection. * Capabilities: Scans for 5000+ known vulnerabilities (CVEs), misconfigurations, and exposed panels. * Severity: Findings are categorized as Critical, High, Medium, Low, or Info. * Usage: Select "Nuclei Vulnerability Scan" in the New Scan modal.

Stealth Port Scanning

(New in v2.0.5) * Stealth Mode: Uses Nmap with evasion flags (-sS, -T2, -D RND:5) to probe ports without triggering IDS/IPS. * Slow & Safe: Designed for stealth, this scan takes longer but reduces detection risk. * Optional dependency with socket fallback: Nmap is not bundled with YADS. If Nmap is not installed, the scanner does not get disabled — it automatically falls back to a lightweight TCP socket scan. See Installing Nmap below for full functionality.

Nmap not installed — Socket Fallback Mode

When Nmap is unavailable, nmap_scanner switches to a built-in TCP socket fallback. The module remains selectable in the scan type selector but shows an amber limited badge to indicate reduced capability.

What still works (socket fallback):

  • TCP connect scan on 20 common ports (21, 22, 25, 53, 80, 110, 143, 443, 465, 587, 993, 995, 3306, 3389, 5432, 6379, 8080, 8443, 8888, 27017)
  • HTTP/HTTPS service detection on web ports
  • Basic banner grab on FTP, SSH, and SMTP ports
  • Port open/closed status and service name

What requires Nmap (not available in fallback):

  • Stealth scanning (-sS SYN scan, -T2 timing, decoy IPs)
  • OS detection and version fingerprinting
  • Full port range scanning (beyond the 20 predefined ports)
  • UDP port scanning
  • NSE script execution

The scan result will contain "method": "socket_fallback" to indicate which mode was used.

Installing Nmap (recommended)

Nmap is an optional external dependency licensed under GPL-2.0. Because YADS calls it as a subprocess (not linked as a library), the GPL does not affect the YADS license. You install it separately on the Docker host or inside the container:

# Option A — on the Docker host (recommended, persists across container restarts)
apt-get install -y nmap        # Debian / Ubuntu
yum install -y nmap            # RHEL / CentOS / Rocky

# Option B — inside a running YADS container (lost on container restart)
docker exec -it yads-api apt-get install -y nmap

# Option C — via YADS Admin UI
# Settings → Scanner Resources → "Install nmap" button
# (runs apt-get install inside the API container automatically)

Note: After installing Nmap, the YADS API container must be restarted for the availability check to re-evaluate. The worker container picks up the binary immediately on next scan execution.

To verify Nmap is detected by YADS, go to Settings → Scanner Resources. The Nmap status indicator will show Installed ✓ when the binary is found.

JavaScript SAST

(New in v2.0.5) * Static Analysis: Automatically downloads and analyzes client-side JavaScript files. * Sink Detection: Identifies potential DOM XSS sinks (e.g. innerHTML, document.write). * Route Discovery: Extracts hidden API routes from JS code.

API Discovery

(New in v2.0.5) Part of the Web Analyzer, this module automatically detects: * Documentation: Finds swagger.json, openapi.yaml, and WSDL files. * Endpoints: Identifies GraphQL endpoints (/graphql) and versioned REST paths (/api/v1/). * Results: displayed in the Web Analysis card on the Target Details page.

SOC2 Compliance Engine

(New in v2.0.5) Real-time scoring of your infrastructure's compliance readiness. * Score: Calculated dynamically (0-100%) based on active scan results. * Penalties: * Expired SSL: -20 pts * Critical CVEs: -15 pts * Risky Ports: -10 pts (e.g. 21, 23, 3389 open to internet) * Public Buckets: -25 pts * Insights: Hover over the score widget on the Dashboard to see specific failings.

Email Security Scanner

(New in v1.20) Analyzes all email authentication and anti-spoofing mechanisms for a domain. * SPF: Validates the Sender Policy Framework record, reports on strictness (-all vs ~all). * DKIM: Checks for DKIM public keys on common selectors. * DMARC: Evaluates policy (none, quarantine, reject) and reporting addresses. * BIMI: Detects Brand Indicator for Message Identification records. * Score: 0–100 composite score; results shown in /email-security analytics view.

HTTP Security Headers

(New in v1.20) Checks all OWASP-recommended HTTP response headers against the target. * Evaluated headers: Strict-Transport-Security, Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, Cross-Origin-*. * Each header is graded Present / Partially Configured / Missing with remediation hints.

Cookie Security Analyzer

(New in v1.20) Audits all cookies set by the target for security attributes. * Checks: Secure, HttpOnly, SameSite (Strict/Lax/None), __Host- prefix usage. * Flags session cookies missing Secure or HttpOnly as high-severity findings.

CORS Misconfiguration Scanner

(New in v1.20) Probes the target with four different Origin header patterns to detect overly-permissive CORS policies. * Patterns: null origin, subdomain wildcard, arbitrary domain, and evil.com. * Detects Access-Control-Allow-Origin: * and credentials-enabled CORS (Allow-Credentials: true with reflected origin).

Certificate Mismatch Scanner

(New in v1.20) Connects via Python's standard ssl library (no external tools needed) to verify the TLS certificate matches the domain. * Detects: hostname mismatches, expired certificates, self-signed certs, and missing SANs. * Results displayed in the SSL card on the Target Details page.

Threat Intelligence Scanner

(New in v1.20) Checks all resolved IPs against three threat intelligence feeds (BYOK API keys required): * AbuseIPDB: Abuse confidence score and report count for each IP. * OTX AlienVault: Pulse count and reputation indicators. * VirusTotal: Malicious/suspicious vote ratio from 90+ engines. * Results are aggregated into an overall threat score and surfaced on the Security Findings page.

Shodan / Censys Host Intelligence

(New in v1.20) Enriches target data using passive internet-wide scan data (BYOK API keys required): * Shodan: Open ports, banners, CVEs, and hostnames from Shodan's database. * Censys: Certificate transparency, exposed services, and autonomous system data. * Data is merged with Nmap results for a unified port/service view without active scanning.

JavaScript Secrets Scanner

(New in v1.20) Downloads and statically analyzes all client-side JavaScript files for hardcoded secrets. * 25+ regex patterns: AWS keys, GitHub tokens, Google API keys, Stripe secrets, private keys, JWTs, and more. * Each match includes the filename, line context, and severity rating. * Findings appear in the Sensitive Data report (/secrets).

Git Exposure Scanner

(New in v1.20) Probes 49 sensitive paths commonly left exposed on web servers. * Checks: /.git/config, /.git/HEAD, /Dockerfile, /.env, /wp-config.php, backup files, and more. * A 200 response for any of these is flagged as a high/critical finding.

Subdomain Takeover Scanner

(New in v1.20) Detects dangling DNS records pointing to cloud services that have been deprovisioned. * 30+ provider fingerprints: GitHub Pages, Heroku, Fastly, Azure, AWS S3, Shopify, Zendesk, and many more. * Logic: If a CNAME points to a provider's domain that returns a known "unclaimed" error page, it is flagged as a high-severity takeover risk.

DNS Zone Transfer (AXFR) Scanner

(New in v1.20) Attempts a zone transfer against all authoritative nameservers for the domain. * A successful transfer reveals the complete internal DNS zone — a critical misconfiguration. * Results show which nameserver allowed the transfer and the number of records leaked.

Security.txt Validator

(New in v1.20) Checks for the presence and validity of a security.txt file per RFC 9116. * Probes both /.well-known/security.txt and /security.txt. * Validates: required fields (Contact, Expires), expiry date (flags expired files), and optional fields (Encryption, Policy, Preferred-Languages).

7. OSINT Brand Monitoring

(New in v2.0.5)

The OSINT module helps you discover unmonitored assets by finding where your brand assets (logos) appear on the web.

Google Cloud Setup (Prerequisite)

To use this feature, your Tenant Admin must configure the Google Cloud Vision API: 1. Enable API: In your Google Cloud Console, enable the "Cloud Vision API". 2. API Key: Create an API Key in "Credentials". * Important: If you restrict your API Key (recommended), ensure Cloud Vision API is checked in the list of allowed APIs. 3. Billing: The Cloud Vision API requires an active Billing Account linked to the project (even for the free tier).

Reverse Image Search

  1. Preparation: Ensure your Tenant Admin has configured the Google Cloud Vision API keys in the Tenant Settings.
  2. Upload: Drag and drop your official logo (PNG/JPG) into the search zone.
  3. Analysis: The system uses Google's Vision API (Web Detection) to find exact copies or visually similar images across the entire web.
  4. Result Filtering:
    • Unknown: Domains not currently in your target list. You can import these with one click.
    • Monitored: Domains you are already tracking.

License & Quotas

This feature is licensed separately per tenant. * Locked State: If you see a "Locked" icon in the sidebar, your tenant has not purchased this add-on. * Usage Limits: Your admin sets a monthly search quota. If exceeded, searches will be blocked until the next cycle.

11. Multi-Tenancy

YADS supports multiple isolated environments (Tenants). * Isolation: Targets, Results, and Users are scoped to a Tenant. * Switching: Users with access to multiple tenants can switch context via the dropdown in the top navigation bar. * Management: Admins can rename tenants and manage memberships via the Tenants page. * Platform Admin: An Admin without a specific tenant sees everything and can manage the tenants themselves.

Webhook Notifications

(New in v2.0.5) Tenants can configure real-time webhooks to integrate with external systems (Slack, Discord, Tines, etc.). 1. Go to Tenant Settings. 2. Scroll to the Webhook Notifications card. 3. Add a URL and select events (e.g., scan_finished, new_asset). 4. Use the Test button to verify connectivity.

12. System Settings & Queue

(Admin Only)

Queue Control

  • Pause/Resume: Stop the background worker from processing new scans. The worker will check for the Resume signal every 60 seconds.
  • Clear Queue: PANIC BUTTON. Cancels all pending and running scans and resets their status to "Idle" in the database. Use this if the system gets stuck.
  • System Reset: Reverts the system to a "Clean State". This removes all scan data and tenants, but preserves user accounts and system configurations.

Configuration

  • Web Timeout: Set global timeout for HTTP requests (default: 10s).
  • Concurrent Limits: Define how many headers scanners run in parallel.

Distributed Workers

YADS supports horizontal scaling through distributed workers across Docker Swarm nodes.

13. AI Intelligence Assistant

The AI Assistant module provides three AI-powered analysis tools accessible from Intelligence → AI Assistant in the sidebar. All features support OpenAI and Anthropic (BYOK) and include rule-based fallbacks when no AI key is configured.

13.1 Configuring AI Providers

AI features require an API key from OpenAI or Anthropic. Keys can be set at two levels:

  • Platform-level: Navigate to Settings → System Config and set OPENAI_API_KEY or ANTHROPIC_API_KEY. This applies to all tenants that have not set their own key.
  • Per-Tenant (BYOK): Tenant administrators can set their own llm_provider, llm_api_key, and llm_model in Tenant Settings → AI Configuration. Tenant keys take priority over platform-level keys.

💡 Rule-Based Fallback: When no API key is configured, all three AI features automatically fall back to sophisticated rule-based logic. The results will be labelled "Rule-based analysis" instead of "AI-generated".

13.2 Finding Prioritization

Automatically ranks all security findings for a selected target by combined exploitability and business impact.

  1. Open Intelligence → AI Assistant.
  2. Select the Prioritization tab.
  3. Choose a target from the dropdown and click Analyze.
  4. Results show each finding with: priority rank, severity badge, exploitability score (1–10), business impact score (1–10), and a one-sentence rationale.

Language: Pass lang=de in the API call body to receive rationale and labels in German.

13.3 Remediation Assistant

Generates step-by-step, actionable remediation guidance for any specific finding.

  1. Open the Remediation tab in the AI Assistant.
  2. Either fill in the finding details manually (title, description, severity, domain), or use the quick-select flow: pick a target, load its findings from the Prioritization endpoint, and click any finding to auto-fill the form.
  3. Click Get Remediation Steps.
  4. The result card shows: numbered steps, effort badge (Low / Medium / High), and reference links.
  5. Use the Copy button to paste the steps into a ticket or report.

The rule-based fallback provides built-in remediation guides for: CORS, XSS, SQL injection, SSL/TLS, HTTP security headers, DNS zone transfer (AXFR), cookie security, CSRF, RCE, and open redirect.

13.4 Natural Language Search

Query your entire findings database across all targets using plain English (or German).

Example queries:

  • show me all critical nuclei findings on api.example.com
  • high severity SSL issues across all domains
  • email security problems
  • DNS findings on staging environments
  • zeige alle kritischen Befunde auf api.example.com (German)

The search uses 500ms debouncing. Parsed filters are shown as chips below the search box (severity, module, domain fragment). Results are sorted by severity and capped at 200 entries. Click any result to navigate directly to the target detail page.

All five AI endpoints accept a lang parameter (en or de). When lang=de is passed:

13.6 Finding Explanation Enterprise

Explains what a specific security finding means in plain language — including what an attacker can do with it and how to remediate it. Available in Intelligence → AI Assistant → Finding Explanation.

  1. Select a target from the dropdown to load its findings, or type a finding title manually.
  2. Choose a finding from the list — the form auto-fills with the finding type, severity, and scanner module.
  3. Review the Sent to AI (preview) box to see exactly what will be transmitted.
  4. Click Explain Finding.
  5. The result card shows three sections: What is this finding?, What can an attacker do?, and How to fix it — plus reference links.

🔒 Privacy (Datensparsamkeit): Only the generic finding type, severity, and scanner module name are sent to the AI provider. Target hostnames, IP addresses, and raw scan data are never transmitted.

The rule-based fallback (active when no AI key is configured) provides built-in explanations for: CORS, XSS, SSL/TLS, DNS zone transfer (AXFR), HTTP security headers, cookie security, and SQL injection.

Generates a management-ready security assessment paragraph for a selected target, suitable for inclusion in board reports or customer presentations. Available in Intelligence → AI Assistant → Executive Summary.

14. Finding Management & Vulnerability Tracking

Beyond detecting vulnerabilities, YADS now lets you track the remediation lifecycle of each finding. Access this feature via Security → Findings.

14.1 Finding Status

Each finding can be assigned one of four statuses:

StatusMeaningBadge Color
OpenNewly detected, not yet addressedSlate
AcknowledgedTeam is aware and is working on itBlue
False PositiveVerified non-issue, excluded from countsGray (strikethrough)
FixedRemediation confirmedGreen (emerald)

To update a finding's status: click the Edit button on any finding row. A modal opens with a status dropdown and an optional notes field. Click Save to persist the change.

Technical note: Status is stored per-tenant and identified by a deterministic SHA-256 hash of domain|module|issue_title. This means the status survives re-scans — a finding marked "Fixed" retains that status even after the next scan run, until the finding actually disappears from results.

14.2 Filtering by Status

  • View False Positive to review your exclusions
  • View Fixed to verify completed remediation work

14.3 CSV Export

The Export CSV button (toolbar, top-right of the findings table) exports the currently filtered view. All active filters are applied — severity, status, module, domain, and date range. The CSV columns are:

  • domain, title, severity, module, status, found_at, notes

This export is suitable for importing into ticketing systems (Jira, ServiceNow) or compliance documentation tools.

20. Standalone & Local Installation

YADS is distributed as a ready-to-run Docker Compose stack via the YADS Container Registry at registry.yads-security.com. No self-compiled builds are required.

Prerequisites

  • Docker Engine 24+ and Docker Compose v2
  • Linux host (Ubuntu 22.04 / Debian 12 recommended) or Docker Desktop on macOS/Windows
  • Registry token (provided with your license via email)
  • Minimum: 2 CPU cores, 4 GB RAM, 20 GB disk

Step 1: Download the Release Package

Download the latest release ZIP from the Support page. The archive contains configuration templates, setup.sh, and documentation — Docker images are pulled from the registry during setup.

Step 2: Run setup.sh

unzip yads_v*_customer_pkg.zip cd yads_v*_customer_pkg chmod +x setup.sh ./setup.sh

The script will:

  1. Prompt for your registry token and run docker login registry.yads-security.com -u yads-readonly
  2. Pull yads-api and yads-worker images from the registry
  3. Ask for your domain, ports, and SSL preference
  4. Generate .env and docker-compose.yml

Step 3: Start

docker compose up -d

Navigate to http://<your-host>:8000 (or your configured domain) to complete the in-app setup wizard.

Manual Image Pull

If you need to pull images separately (e.g. air-gapped pre-staging):

docker login registry.yads-security.com -u yads-readonly # enter registry token when prompted docker pull registry.yads-security.com/yads/yads-api:latest docker pull registry.yads-security.com/yads/yads-worker:latest

Updates

docker pull registry.yads-security.com/yads/yads-api:latest docker pull registry.yads-security.com/yads/yads-worker:latest docker compose up -d --force-recreate

Always create a backup before updating (Settings → Backup & Restore).

19. Asset Discovery

The Asset Discovery module automatically detects subdomains and related infrastructure for a target domain — without running active network scans.

How It Works

  • Passive Techniques: Certificate Transparency logs (crt.sh), DNS databases, Wayback Machine, and public OSINT sources.
  • Recursive Discovery: Newly discovered subdomains are automatically registered as additional targets and scanned in turn (configurable).
  • Automatic Queue Integration: Discovered assets are immediately added to the scan queue — no manual input required.

Configuration

  • Enable Auto-Queue Subdomains under Settings → Scan Settings.
  • Recursive mode can be limited to a maximum depth to prevent unbounded growth of the target list.
  • Discovery results are available in the DNS Scanner report for each target.

Tip: Combine Asset Discovery with the DNS Health Check module to automatically archive unreachable subdomains.
