2. Installationsanleitung (Docker)

Voraussetzungen

  • Docker Engine (v20.10+)
  • Docker Compose (v2.0+)
  • Lizenzschlüssel (wurde Ihnen per E-Mail zugesendet)

Schritt 1: Images laden

Entpacken Sie das ZIP-Archiv und laden Sie die Docker-Images:

docker load < yads-images.tar.gz

Überprüfung:

docker images | grep yads # Sollte yads-api und yads-worker listen

Schritt 2: Starten

Wechseln Sie in das Verzeichnis und starten Sie den Stack:

docker compose up -d

3. Setup Wizard (Automatische Einrichtung)

Öffnen Sie http://localhost:8000 in Ihrem Browser.

Sie werden automatisch zum Setup Wizard weitergeleitet.

  • Lizenz: Geben Sie Ihren Lizenzschlüssel ein.
  • Datenbank: Setzen Sie ein sicheres Passwort für die Datenbank.
  • Initialisierung: Wählen Sie zwischen Upgrade (Daten behalten) oder Reset.
  • Admin: Erstellen Sie Ihren persönlichen Administrator-Account.

Fertig! YADS ist nun vollständig konfiguriert und einsatzbereit.

3. Technische Architektur

YADS basiert auf einer Microservices-Architektur, orchestriert durch Docker Compose.

yads-api

Backend (FastAPI). Verwaltet Daten, Benutzer und die API.

yads-worker

Hintergrund-Dienst. Führt Scans (Nuclei, Nmap, Chrome) aus.

PostgreSQL

Hauptdatenbank für Persistenz.

Redis

Task Queue & Caching Layer.

4. Verteilte Worker (Optional)

Für groß angelegte Deployments unterstützt YADS horizontale Skalierung durch mehrere Worker-Nodes in einem Docker Swarm Cluster.

Voraussetzungen

  • Docker Swarm auf allen Nodes initialisiert
  • Netzwerkverbindung zwischen Manager und Worker-Nodes
  • Redis von allen Nodes erreichbar (Overlay-Netzwerk)

Schritt 1: Docker Swarm initialisieren

Auf dem Manager-Node (wo yads-api läuft):

docker swarm init --advertise-addr <MANAGER_IP>

Dies gibt einen Join-Befehl aus. Führen Sie ihn auf jedem Worker-Node aus:

docker swarm join --token <TOKEN> <MANAGER_IP>:2377

Schritt 2: Worker-Registrierungstoken generieren

In der YADS-Oberfläche gehen Sie zu Einstellungen → Verteilte Worker und klicken Sie auf "Token generieren".

Kopieren Sie das Token – Sie benötigen es für jeden sekundären Worker.

Schritt 3: Sekundäre Worker bereitstellen

Verwenden Sie die Swarm-Deployment-Datei aus dem Release:

# Umgebungsvariablen setzen export WORKER_REGISTRATION_TOKEN=<ihr-token> export REDIS_URL=redis://<manager-ip>:6379/0 # Worker im Swarm bereitstellen docker stack deploy -c docker-compose.swarm.yml yads

Schritt 4: Worker überprüfen

In der YADS-Oberfläche unter Einstellungen → Verteilte Worker sollten Sie sehen:

  • Aktive Worker: Liste aller verbundenen Worker-Nodes
  • Lastverteilung: Aktuelle Task-Anzahl pro Worker
  • Gesundheitsstatus: Heartbeat-Status (aktualisiert alle 30s)
💡 Tipp: Worker verbinden sich nach Netzwerkunterbrechungen automatisch wieder. Tasks von ausgefallenen Workern werden automatisch neu eingereiht.

Worker-Steuerung

Sie können Worker ohne Neustart der Dienste verwalten:

  • Pausieren: Keine neuen Tasks akzeptieren (aktuelle beenden)
  • Fortsetzen: Wieder neue Tasks akzeptieren
  • Entleeren: Ordentlich herunterfahren nach Abschluss aller Tasks

5. One-Click Updates

YADS enthält einen In-App Update-Mechanismus, der das neueste Docker-Image lädt und einen kontrollierten Neustart ohne manuellen Eingriff durchführt.

Funktionsweise

  1. Nach Updates suchen: Gehen Sie zu Einstellungen und klicken Sie auf "Nach Updates suchen"
  2. Änderungen prüfen: Sehen Sie im Changelog, was neu ist
  3. Update starten: Klicken Sie auf "Update starten", um den Prozess zu beginnen

Update-Prozess

Der Update-Prozess ist vollständig automatisiert:

1️⃣
Queue pausieren

Scan-Queue wird pausiert

2️⃣
Tasks abschließen

Aktive Scans werden beendet

3️⃣
Image laden

Neue Version herunterladen

4️⃣
Neustart

Kontrollierter Neustart

⚠️ Wichtig: Erstellen Sie vor dem Update ein Backup. Updates können während der Vorbereitungs-/Download-Phase abgebrochen werden, aber nicht mehr nach Beginn des Neustarts.

Manuelles Update (Alternative)

Falls Sie das Update lieber manuell durchführen oder das In-App Update fehlschlägt:

# Neuestes Image laden docker pull yads/yads:latest # Dienste neu starten docker compose up -d --force-recreate

6. SIEM-Integration (Splunk)

YADS unterstützt die Echtzeit-Weiterleitung von Sicherheits-Audit-Ereignissen an Splunk für zentralisiertes Monitoring und SIEM-Korrelation. Ereignisse sind am MITRE ATT&CK Framework ausgerichtet.

Konfiguration

Fügen Sie die folgenden Umgebungsvariablen zu Ihrer docker-compose.yml hinzu:

environment: - SPLUNK_HEC_URL=https://splunk.example.com:8088/services/collector - SPLUNK_HEC_TOKEN=ihr-hec-token-hier

Ereignistypen

Die folgenden Sicherheitsereignisse werden mit MITRE ATT&CK Technik-IDs an Splunk weitergeleitet:

Login-Ereignisse

Erfolg, Fehlschlag (T1078, T1110)

Passwortänderungen

Benutzer & Admin-Reset (T1098)

MFA-Ereignisse

Aktivieren, Deaktivieren, Reset (T1556)

Benutzerverwaltung

Erstellen, Löschen, Rollenänderung (T1136)

💡 Tipp: Erstellen Sie ein Splunk-Dashboard mit MITRE-Technik-IDs, um YADS-Ereignisse mit anderen Sicherheitstools zu korrelieren. Beispielsuche: index=yads mitre_technique_id=T1110*
